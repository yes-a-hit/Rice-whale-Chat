# 提示词分层

一次请求里，提示词分三层注入，越靠上越稳定、越贵；越靠下越省、越临时。

```
┌─ system 字段（每轮都发）──────────────────────────────┐
│  1. 系统提示词（主提示词）                            │
│  2. 角色卡（人设补充，拼在后面，不覆盖前者）            │
└──────────────────────────────────────────────────────┘
┌─ messages 数组（只注入一次，随历史滚动）──────────────┐
│  3. 辅助提示词（反鲸八股等写作规则）                   │
│  4. 历史后指令（格式/收尾约束）                        │
└──────────────────────────────────────────────────────┘
```

## 1–2 系统层

`resolveSystemPrompt()` 把两段按固定顺序拼起来：

```ts
[systemPrompt, characterPrompt].filter(Boolean).join('\n\n')
```

- **系统提示词在前**，定行为基调；
- **角色卡在后**，做具体人设补充；
- 都空才回落官方那句「该助手为DeepSeek…」。

放在 `system` 里是因为这里优先级最高，而且同一段文本能吃到 DeepSeek 的 prompt cache
（命中价 0.2 元/百万，未命中 2 元/百万），所以长一点不算太亏。

## 3–4 辅助层

辅助提示词和历史后指令**不进 system**，而是当作一次性的对话插入：

```ts
{ role: 'user',      content: '【规则层】\n' + aux + tail }
{ role: 'assistant', content: '明白，按这套规则来。' }
```

规则：

- 判断依据是历史里有没有以 `【规则层】` 开头的消息（`hasAuxInjected`）；
- 有就跳过，没有就插一条——所以**只在新会话第一条注入一次**；
- 上下文被压缩、早期消息被裁掉后，标记自然消失，下一次请求会**自动重新注入**；
- 开关关掉就整段不发。

为什么这么做：几千字的规则每轮都塞进 system，等于每轮都付一遍输入费。
插进历史只付一次，之后随历史一起被压缩掉。

## 预装内容

`DEFAULT_AUX_PROMPT` 是「反鲸八股」规则（约 200 字）：

1. 不用「首先/其次/最后」「综上所述」这类三段式脚手架；
2. 不用「不是…而是…」「不仅…而且」凑节奏；
3. 少用「深刻地」「极大地」「赋能」「抓手」；
4. 不排比、不堆破折号；
5. 给数字、给例子、给名字；
6. 结尾不总结、不喊口号、不反问。

短是刻意的：规则越长，首轮成本和压缩前的历史负担越大。要加规则先想清楚值不值。

## 修改位置

设置 → 扩展：

- 启用辅助提示词（开关）
- 辅助提示词（多行，可恢复默认）
- 历史后指令（多行，默认空）

代码：`src/services/chat/promptLayers.ts`（组装与判断）、`src/services/chat/reply.ts` 的
`toRequestMessages()`（插入点）。
